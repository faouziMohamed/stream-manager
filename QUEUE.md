## Known issues

- **A failed page load can retry in a loop while the database refuses connections.**
  Seen 2026-10-19 on `/console/payments`: the tab requested the document
  repeatedly and the server log showed `AggregateError` / `internalConnectMultiple`
  from Postgres — Aiven allows 20 connections and the app's old 5-connection dev
  pool, competing with the IDE and other tools, left no room. The loaders throw
  by design, and the dev client retries the document while the failure lasts.
  Mitigated: the dev pool now defaults to 2 connections (`DB_POOL_MAX`
  overrides), with `idle_timeout: 20` so idle slots return. A fresh tab on a
  healthy server issues one document request. If it recurs, check
  `pg_stat_activity` and the server log before assuming a UI loop.

- **Migration history was repaired by hand once.** `0010_simplify_backoffice`
  never ran on this database, so the runner tried to replay it and failed on the
  first object that had already drifted. `0010` and `0011` were recorded in
  `drizzle.__drizzle_migrations` directly, and `0010`'s statements were then
  executed idempotently (the drops were approved separately, and the rows they
  removed were dumped first). `pnpm db:migrate` now exits 0 with nothing
  pending, and the schema matches the journal. Nothing downstream depends on
  this note; it is here so a future reader is not surprised that two migrations
  claim to have run on a date their file hashes suggest otherwise.
